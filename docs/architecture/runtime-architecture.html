Runtime & Service Lifecycle

KeyPath launches and supervises a Kanata worker in the signed-in user’s session on macOS 27.

Process and control boundaries

The app owns the worker and its lifecycle. The worker captures keyboard events, runs Kanata through the Rust host bridge, and emits remapped events.

Engine socket

The worker reports the path to its Unix-domain socket. The socket is mode 0600 in a private directory of mode 0700. The server verifies the launching app’s user, process ID, process version, and code signature on every connection. The app uses this channel to reload configuration, query layers, control virtual keys, and receive engine events.

Lifecycle and health

Start or repair
InstallerEngine inspects prerequisites and delegates runtime actions to ServiceLifecycleCoordinator. The coordinator starts the worker and verifies the report for this launch, control responsiveness, and input capture readiness before reporting success.
Stop or restart
ServiceLifecycleCoordinator serializes lifecycle requests and manages the owned worker. The worker watches the app’s process and exits when its owner exits. Before loading anything, the worker refuses to start unless its config is the canonical ~/.config/keypath/keypath.kbd (compared with realpath, .. refused) and its named owner’s running code satisfies KeyPath’s own designated requirement (SessionWorkerLaunchCheck). Another process can still launch the signed binary, but the worker then runs only the user’s own config, and only the KeyPath owner can reach its engine socket. The owner check does not prove that owner launched the worker: NSWorkspace launches leave no channel for a secret.
Read health
ServiceHealthChecker reads current session readiness through the provider configured by the app. Process liveness, control responsiveness, and input capture are distinct signals. Use PermissionOracle for permission evidence.
Recover
The worker can stop when Secure Input takes over. The coordinator supervises recovery after session transitions and recoverable failures, and reports failures that need user action.

Save and reload rules

Managed rule edits update the JSON stores and generated Kanata configuration in one recoverable write.

Validate and stage
RuleCollectionsManager prepares the edit. SaveCoordinator validates and stages the files under ConfigurationOperationGate, which serializes writers.
Apply or defer
ConfigReloadCoordinator asks the engine to reload. An accepted or pending reload lets the save settle. Pending means the files are saved and runtime application is deferred.
Restore on failure
A rejected reload triggers restoration of the previous files and a recovery reload. The save result preserves the original error and any recovery failure.

Use ConfigReloadCoordinator for runtime reloads and ServiceLifecycleCoordinator for start, stop, and restart.
