# Automatic driverless Caps setup

A configuration with a Caps Lock behavior authorizes internal keyboard setup. Parent admission validates the managed-Caps profile without demanding manual selection. Before startup, the lifecycle coordinator discovers exactly one compatible keyboard, creates a current-boot selection, checks the generation again, and persists it. The worker still validates selection and acquires the original mapping lease; conflict checks, F18 collisions, all-up admission, journals and restoration remain unchanged. Explicit Disable in advanced Caps settings suppresses automatic setup. Discovery never writes an OS mapping. Ambiguous keyboards remain a refusal. This is fresh current-boot discovery, not persistent device identification across reboots.

Built-in Apple keyboards on the Air report AppleHIDKeyboardEventDriverV2, FIFO, Built-In=true, and zero VID/PID. The external-fixture-only parser rejected them before any remapping. Accept this witnessed class with its built-in/transport evidence and carry that evidence in the boot-scoped device identity. Zero IDs without that evidence remain invalid. A read-only locator probe on the Air returned exactly the discovered event-service registry ID; readback and lease ownership checks still apply.
