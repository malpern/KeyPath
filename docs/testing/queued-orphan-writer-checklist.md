# Queued orphan Caps writer acceptance

This experiment will test whether a queued real writer can outlive its owner and mutate later while recovery remains refused. It does not prove worker death inside an opaque HID mutation call. Current seam: product `60dfd2d30`, with post-signal `_exit` and a new child session via SETSID; DEBUG only. Earlier actual-child trials failed and remain failed. Non-HID probes support this correction but do not establish actual HID survival. Root is the sole live controller. Use canonical owned disposable VM admission and preserve original receipts; no replay to turn a refusal into a pass.

1. Create a fresh owned guest and independently bind lease/provider, boot epoch and boot UUID, cutoff, UID502 account/home, exact signed artifact, and exact attached ESP32 keyboard service identity. Grant normal required permissions. Establish original mapping and profile bytes/digests, no existing intent/marker/checkpoint, and no foreign product processes. This is a mapping-only experiment: no held input or target events are required.
2. Configure the existing managed Caps selection and F18 reservation. Set `KEYPATH_EXPERIMENTAL_CAPS_TERMINATE_WITH_QUEUED_WRITER` to the exact decimal selected registry ID; leave the after-joined experiment unset. Use the ordinary app launch/Start path once. Record actual parent/worker owner identity; do not inject a guessed nonce or generation.
3. Read the intent, mutation marker, and `caps-mapping-queued-writer-checkpoint.json` with existing owned directory/file guards: UID502, directory700, files600, regular single-link, no symlink, bounded stable bytes. Record raw digests. Require phase `queued-writer-before-execution`, exact owner including boot UUID/nonce/generation, and exact selected device in checkpoint and intent. Marker owner must match. Independently prove the old worker PID absent systemwide.
4. Before any signal, independently inspect the checkpoint child PID in this same fresh boot. Require UID502, full executable `/usr/bin/hidutil`, exact existing writeArguments for the selected device and applied mapping, and suspended process state. Record current parent identity/reparenting observation rather than assuming its parent PID still equals the dead worker. Checkpoint alone is never authority to signal a PID. Require current selected registry identity unchanged and original mapping still present; preserve intent/marker/checkpoint byte digests unchanged.
5. Observe surviving parent behavior. Through normal UI Start/Restart, require retained-uncertainty refusal without an additional writer or mapping change. Then normally quit the surviving parent, prove its absence, launch a fresh parent and use normal Start if required. Require the same refusal and no live replacement worker. Record the actual user-facing error plus source-backed refusal ordering; distinguish a Start never attempted or unrelated permission refusal. Re-read original mapping and unchanged retained files before allowing the queued writer to proceed.
6. Immediately revalidate fresh boot, lease/cutoff, exact child UID/PID/executable/arguments/suspension, selected device and retained file digests. Root may issue SIGCONT to that exact child once only after these proofs. Do not resume an unverified or reused PID. Record the signal result, then boundedly observe child exit and independently read back the applied mapping on the same registry identity. Child disappearance alone does not prove successful mutation; mapping readback does not establish a child exit status unless independently available to its current reaper.
7. Use normal Start again in the fresh parent. Require refusal despite the now-applied mapping, no new writer/worker, and byte-identical intent, mutation marker and checkpoint. Do not clear uncertainty or manually restore mapping to obtain acceptance. Record mapping-only result separately from physical remapping or all-modifier clearance, neither of which this campaign tests.
8. Stop the owned app through normal UI and observe exact process absence. If the child remains suspended or alive, cleanup may target it only after renewed boot/PID/UID/full executable/exact argument proof; record cleanup and confirmed disappearance. If that identity cannot be established, do not guess or signal by name. Preserve uncertain files/evidence. Detach only the exact owned fixture with ownership verification, then canonically destroy the disposable guest and independently verify provider removal and fixture detachment. Do not use a surviving suspended child as a reason to reuse the guest.

The spawn branch closes inherited descriptors, redirects stdio to `/dev/null`, and supplies an empty environment. The checkpoint is exclusive and fsynced before owner termination; any checkpoint or termination failure cleans up and joins the still-owned child and leaves the mutation marker. These failure paths have source review and inert policy coverage, not live execution proof. PID reuse remains a controller risk after reparenting: every later resume/cleanup needs a new independent identity observation bound to the same boot. A failed or incomplete campaign remains failed/incomplete; retain partial facts and dispose rather than retrying within it.
