## Process constraints

- One canonical CREATE command; no new maintained launcher wrapper. Root stores one durable intent and actual result per operation in a fresh private evidence directory.
- Keep exact ownership, cutoff, permission isolation, physical input and independent cleanup safeguards. Cut duplicate plumbing, not those safeguards.
- No repeated broad lab qualification after a product experiment refusal. Classify failures using the existing failure-ownership convention and ledger.
- Test actual signed artifact metadata and actual entry-point admission; avoid fixture substitutions that hide stale production bindings.
- Source-only review is not live acceptance. Fresh install/consent/identity/timing/configuration must bind current source bytes; no old-scope or uncertain mutation replay.
- Preserve historical code/receipts, but stop adding adapter layers. Consolidate touched code when a demonstrated failure requires changing it; no broad harness rewrite first.
- Report completed gates and unresolved questions, not a milestone-count percentage or unsupported completion ETA. Model routing is based on the task boundary; parallel agents handle independent source work, never competing live control.
